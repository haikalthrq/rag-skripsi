Skripsi S1 — membangun dan mengevaluasi sistem RAG berbasis dokumen statistik BPS Indonesia.
Bahasa: Python 3.11.9 | Repo: rag-skripsi | Branch aktif: main

Environment / Hardware:
  - Lokal (laptop): Windows | GPU RTX 4050 6GB
    → Embedding: Qwen3-Embedding-4B-Q8_0.gguf via llama.cpp (CPU only, hemat VRAM)
    → Generator: Qwen3-4B-Instruct-2507-FP8 via HuggingFace transformers (GPU)
  - Cloud (Vast AI): Linux | GPU RTX 3090 24GB VRAM (TARGET HARDWARE BERIKUTNYA)
    → Embedding: Qwen3-Embedding-4B (HuggingFace, safetensors) via sentence-transformers (GPU)
    → Generator: Qwen3-4B-Instruct-2507 BF16 (HuggingFace transformers, GPU)
    → Virtual Environment: .venv di folder rag-skripsi (requirements.txt terinstall)
    → CATATAN: Hardware sebelumnya A100 SXM4 40GB sudah tidak aktif.
               Run definitif berikutnya akan dilakukan di RTX 3090 24GB.

Tujuan:
  - Bandingkan 3 metode chunking: element_based, maxmin_semantic, recursive
  - Embedding: Qwen3-Embedding-4B (HuggingFace) — Vast AI; GGUF — Laptop
  - Generator: Qwen3-4B-Instruct-2507 (FP8/BF16 tergantung GPU)
  - Vector DB: ChromaDB (persistent, lokal di data/chroma/)
  - Evaluasi retrieval: Precision@k, Recall@k, MRR
  - Evaluasi generasi: BLEU (sacrebleu), ROUGE-L Recall (rouge-score)

Dokumen BPS (10 dokumen, di data/raw/ + scripts/gt_raw/):
  benchmark-indeks-konstruksi, benchmark-statistik-konstruksi,
  cerita-data (mismatch pendidikan-pekerjaan), indeks-unit-value-ekspor-impor,

Pipeline Ground Truth (2 tahap):
  TAHAP 1 — scripts/build_candidates_v3.py (Oracle Pooling, BUKAN ChromaDB)
    Input : qa_gold xlsx + data/chunked/{method}/*.json
    Output: retrieval_relevant_chunks_candidate_v3_evidence_aware.xlsx/.csv
    Fungsi: scan semua chunk vs QA gold → scoring → top-5 kandidat per grup
    Metodologi: oracle pooling (text-matching) untuk hindari circular dependency
    Hasil (2026-05-17): 413 baris, 90 grup (30 query × 3 metode), 0 not_found

  TAHAP 2 — Anotasi Manual via src/streamlit/app.py
    Input : kandidat v3 xlsx
    Output: data/ground_truth/retrieval_labels_final.xlsx/.csv
    Status: SELESAI — 416/416 baris dianotasi (label 0/1/2)

Ground Truth JSON (output evaluasi retrieval):
  data/ground_truth/qa_pairs_strict.json   — label == 2, 58 chunk relevan
  data/ground_truth/qa_pairs_lenient.json  — label >= 1, 175 chunk relevan
  Format: [{id, question, reference_answer, relevant_chunk_ids: {method: [ids]}}]

  Distribusi query dengan GT chunk per metode:
    Strict  (label=2): element 15/30, maxmin 18/30, recursive 15/30
    Lenient (label≥1): element 28/30, maxmin 29/30, recursive 29/30
  Query tanpa GT chunk → metrik retrieval = N/A (by design, bukan bug)

Label anotasi:
  2 — Relevan Utama: chunk cukup untuk menjawab question
  1 — Pendukung: relevan sebagian / konteks tambahan
  0 — Tidak Relevan
  suggested_label di kandidat adalah SARAN algoritma, BUKAN label final

CATATAN MRR: |Q| dalam agregasi MRR = hanya query yang punya GT chunk (bukan 30).
  Ini pilihan metodologis yang valid — query tanpa GT tidak bisa dinilai retrieval-nya.
  Pastikan definisi |Q| di laporan skripsi konsisten dengan ini.

4. KOMPONEN TEKNIS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Chunking:
  element_based   : unstructured partition_pdf hi_res → elemen semantik
                    composite chunking (bukan 1 elemen = 1 chunk)
                    schema: {text, chunk_id, metadata:{chunk_type, element_types,
                    section_title, page_numbers, source_file, text_as_html, ...}}
  maxmin_semantic : MaxMin semantic diversity (implementasi custom, bukan PyPI)
  recursive       : LangChain RecursiveCharacterTextSplitter dengan overlap
  File chunks: data/chunked/{method}/{doc_id}_chunks.json

Embedding:
  Lokal (RTX 4050):
    Model : Qwen3-Embedding-4B-Q8_0.gguf (via llama.cpp)
    Device: CPU only (hemat VRAM untuk generator)
    n_batch: 64 (diubah dari 512 untuk hindari OOM)
  Cloud (Vast AI RTX 3090):
    Model : Qwen3-Embedding-4B (HuggingFace, safetensors) via sentence-transformers
    Device: GPU (CUDA)
    Path  : models/Qwen3-Embedding-4B/
  Enrichment: enrich_table_chunk_texts() di src/embedding/io.py
    → Parse text_as_html tabel + prefix judul dari chunk sebelumnya
    → Hanya memengaruhi data/embeddings/ dan ChromaDB, TIDAK ubah data/chunked/

ChromaDB:
  Path: data/chroma/ (di Vast AI: symlink ke /workspace/chroma/)
  Collections: collection_element_based, collection_maxmin_semantic, collection_recursive
  ID chunk format: {file_stem}_{original_index} — terverifikasi cocok 100% dengan GT JSON

Generator:
  Lokal (RTX 4050):
    Model: Qwen3-4B-Instruct-2507-FP8 (HuggingFace transformers, lokal di models/)
    VRAM: ~5 GB (auto max_memory: GPU=5GiB, CPU=16GiB)
  Vast AI (RTX 3090 24GB):
    Model: Qwen3-4B-Instruct-2507 BF16 (HuggingFace transformers, lokal di models/)
    VRAM: ~8-9 GB untuk bobot; KV cache tumbuh bertahap (bukan alokasi muka)
    Estimasi VRAM puncak (generator + embedder + KV cache): ~20-21 GB → aman di 24GB
  Fallback: Qwen/Qwen3-4B-Instruct-2507 (HF Hub)
  BUKAN Thinking model — Instruct dipilih karena lebih stabil untuk evaluasi faktual
  Parameter LOCKED (sesuai rekomendasi resmi model card Qwen3-4B-Instruct-2507):
    Temperature=0.7, Top-P=0.8, Top-K=20, MinP=0, Max-tokens=16384
    CATATAN: max_tokens=16384 adalah batas atas (bukan alokasi muka).
             Jawaban rata-rata ~400 char (~150-250 token), terpanjang ~1400 token.
             Sebelumnya 1024 (terlalu kecil, ~8 jawaban terpotong) — sudah diubah ke 16384.

Metrik Evaluasi:
  Retrieval : Precision@k, Recall@k, MRR — pure Python di src/evaluation/metrics.py
              Tervalidasi unit test T10–T18 (20/20 pass)
              MRR: RR(q)=1/rank_relevant(q), MRR=mean(RR) atas query yang punya GT chunk
  Generasi  : BLEU via sacrebleu.corpus_bleu([response],[[reference]]) / 100
              ROUGE-L via rouge_score.RougeScorer, rouge_type='rougeL', mode='recall',
              use_stemmer=False (exact match, cocok Bahasa Indonesia)
  CATATAN: ragas, rank-eval, rapidfuzz TIDAK dipakai (dihapus dari requirements.txt)

Streamlit Apps:
  src/streamlit/app.py      — annotation tool v3 (anotasi sudah selesai)
  src/streamlit/rag_chat.py — RAG demo (single/compare mode, inline BLEU/ROUGE)
    DEFAULT_TOP_K=8, slider max=10
    DEFAULT_MAX_TOK=16384 (sesuai rekomendasi resmi)
    Batch eval output: results/final/generation/ (dibuat otomatis)
    Relevance mode: radio button (All, Strict, Lenient) — user-selectable
    Quick eval: Q005, Q010, Q011, Q013, Q020
    st.iframe(height=1) untuk JS injection (bukan components.html yang deprecated)
    Cache model: @st.cache_resource — tidak reload per query
    Embedder mode: 'huggingface' (HF safetensors) di Vast AI; 'gguf' di laptop
  Versi Streamlit: 1.57.0
