1. HIGHLIGHTS
================================================================================

We introduce the updated version of the Qwen3-4B-BF16 non-thinking mode, named
Qwen3-4B-Instruct-2507-BF16, featuring the following key enhancements:

  Significant improvements in general capabilities, including instruction
    following, logical reasoning, text comprehension, mathematics, science,
    coding, and tool usage.

  Substantial gains in long-tail knowledge coverage across multiple languages.

  Markedly better alignment with user preferences in subjective and open-ended
    tasks, enabling more helpful responses and higher-quality text generation.

  Enhanced capabilities in 256K long-context understanding.

5. QUICKSTART
================================================================================

--------------------------------------------------------------------------------
5.1 Basic Usage with Transformers
--------------------------------------------------------------------------------

from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "Qwen/Qwen3-4B-Instruct-2507-BF16"

# Load tokenizer and model
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype="auto",
    device_map="auto"
)

# Prepare input
prompt = "Give me a short introduction to large language model."
messages = [{"role": "user", "content": prompt}]
text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
)
model_inputs = tokenizer([text], return_tensors="pt").to(model.device)

# Generate
generated_ids = model.generate(
    **model_inputs,
    max_new_tokens=16384
)
output_ids = generated_ids[0][len(model_inputs.input_ids[0]):].tolist()
content = tokenizer.decode(output_ids, skip_special_tokens=True)
print("content:", content)

Notes:
  - apply_chat_template is mandatory for correct chat formatting.
  - add_generation_prompt=True adds the assistant prompt so the model starts answering.
  - max_new_tokens=16384 follows the recommended output length from the documentation.
  - output_ids is sliced to contain only the model's answer, not the input prompt.

--------------------------------------------------------------------------------
5.2 Deployment with SGLang / vLLM
--------------------------------------------------------------------------------

SGLang:
  python -m sglang.launch_server
      --model-path Qwen/Qwen3-4B-Instruct-2507-BF16
      --context-length 262144

vLLM:
  vllm serve Qwen/Qwen3-4B-Instruct-2507-BF16
      --max-model-len 262144

NOTE: If you encounter OOM, reduce context length, e.g., to 32,768.

--------------------------------------------------------------------------------
5.3 Agentic Use with Qwen-Agent
--------------------------------------------------------------------------------

Qwen3 excels in tool calling. We recommend Qwen-Agent to maximize agentic ability.

from qwen_agent.agents import Assistant

llm_cfg = {
    'model': 'Qwen3-4B-Instruct-2507-BF16',
    'model_server': 'http://localhost:8000/v1',
    'api_key': 'EMPTY',
}

tools = [
    {'mcpServers': {
        'time': {'command': 'uvx', 'args': ['mcp-server-time', '--local-timezone=Asia/Shanghai']},
        'fetch': {'command': 'uvx', 'args': ['mcp-server-fetch']}
    }},
    'code_interpreter',
]

bot = Assistant(llm=llm_cfg, function_list=tools)

messages = [{'role': 'user', 'content': 'https://qwenlm.github.io/blog/ Introduce the latest developments of Qwen'}]
for responses in bot.run(messages=messages):
    pass
print(responses)

6. BEST PRACTICES
================================================================================

--------------------------------------------------------------------------------
6.1 Sampling Parameters (Official Recommendation)
--------------------------------------------------------------------------------

  Temperature = 0.7
  TopP        = 0.8
  TopK        = 20
  MinP        = 0

For supported frameworks, presence_penalty can be set between 0 and 2 to reduce
endless repetitions. However, a higher value may occasionally result in language
mixing and slight performance decrease.

--------------------------------------------------------------------------------
6.2 Output Length
--------------------------------------------------------------------------------

  Most queries: 16,384 tokens (recommended for instruct models)

For short answers, still limit max_new_tokens for faster inference.

--------------------------------------------------------------------------------
6.3 Standardize Output Format
--------------------------------------------------------------------------------

For benchmarking, use prompts that force consistent output format:

Math problems:
  Include: "Please reason step by step, and put your final answer within \boxed{}."

Multiple-choice:
  Add: "Please show your choice in the answer field with only the choice letter, e.g., \"answer\": \"C\"."

================================================================================
7. NOTES FOR RAG PIPELINE
================================================================================

Role in RAG:
  This model is the generator, NOT the retriever. Use a separate embedding model
  (e.g., Qwen3-Embedding-4B) for document embedding and retrieval.

Architecture:
  1. User asks a question.
  2. Embedding model embeds the query.
  3. Vector DB retrieves top-k relevant chunks.
  4. Prompt is built from instruction, retrieved chunks, and question.
  5. Qwen3-4B-Instruct-2507-BF16 generates the answer.
  6. Evaluate retrieval and generation separately.

Example RAG prompt:

You are a document-based QA assistant. Answer based only on the provided context.
If the answer is not in the context, respond: "Not found in context."

[CONTEXT]
{retrieved_chunks}

[QUESTION]
{question}

[ANSWER]

Parameter recommendations for factual RAG:
  Use lower temperature (0.1-0.3) for stable factual answers.
  Use official Temperature=0.7 for more open-ended tasks.
  Limit max_new_tokens to the expected answer length.
  Use consistent output format for automatic evaluation.

================================================================================
8. LIMITATIONS
================================================================================

  This model is non-thinking mode only.
  No <think> blocks in output.
  Hardware requirements are not detailed in the PDF documentation.
  Full context 262,144 tokens may cause OOM on limited hardware.
  Some benchmarks do not always outperform specific competitors.
  Aider-Polyglot and TAU2-Telecom are not the top scores for this model.

Technical checks required:
  transformers version must be recent (>= 4.51.0).
  Chat template must be used.
  Context length must match available VRAM.
  For agentic tool use, parser and tool schema must be tested.
  For automatic evaluation, output must be standardized.

10. ONE-PARAGRAPH SUMMARY FOR AI AGENT
================================================================================

Qwen/Qwen3-4B-Instruct-2507-BF16 is a 4B-parameter causal language model for text
generation and instruction following, updated from the previous Qwen3-4B
non-thinking mode. It supports 262,144 native context tokens, 36 layers, GQA
with 32 Q heads and 8 KV heads, 4.0B parameters (3.6B non-embedding), BF16
tensor type, and Apache 2.0 license. The model does not generate <think>
blocks and does not require enable_thinking=False. Use it as the generator in
a RAG pipeline; do NOT use it as an embedding model. Use transformers >= 4.51.0
to avoid KeyError: 'qwen3'. For OpenAI-compatible deployment, use
sglang >= 0.4.6.post1 or vllm >= 0.8.5. Official sampling recommendation:
Temperature=0.7, TopP=0.8, TopK=20, MinP=0. Recommended output length for most
queries: 16,384 tokens. For factual RAG, consider lower temperature (0.1-0.3).
